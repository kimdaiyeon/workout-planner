# 운동 자세 피드백 플랫폼 — 프로젝트 정리

> Claude Code로 넘어가기 전 기획·검토 내용 정리 (2026-10-06 채팅 기준)

## 1. 한 줄 요약

기준(정답) 운동 영상과 사용자가 실제로 운동하는 영상을 비교해서, 세트가 끝난 뒤 쉬는 시간 동안 "몇 번째 반복에서 무엇이 틀렸는지"(팔 각도, 속도 등)를 알려주는 앱.

## 2. 요구사항 (대연이 정의한 내용)

### 2-1. 핵심 기능
- 내가 제공하는 영상이 **정답 영상**이다.
- 정답 영상의 **팔 각도, 속도** 등을 기준으로, 사용자가 앱을 켜고 운동하는 영상과 비교한다.
- "팔이 너무 기울었다", "너무 빠르다" 같은 피드백을 제공한다.

### 2-2. 사용자 이용 흐름
1. 앱 시작
2. 오늘 운동할 부위 선택 (예: 어깨)
3. 해당 부위 운동 3~5개 추천
   - 세부 타겟 (앞 어깨, 옆 어깨, 뒤 어깨 등)
   - 운동 시간 선택 (30~60분)
   - 운동 기구 선택 (머신, 바벨, 케이블 등)
4. 선택한 운동의 예시 영상 재생 → 1세트 진행 안내
   - 운동 하나당 보통 8~15회 × 4세트
5. 사용자가 운동하는 모습을 촬영 (브이로그처럼)
6. 1세트 종료 후, 쉬는 시간 동안 기준 영상과 관절 각도·속도 등을 비교한 피드백 제공
   - 몇 번째 반복에서 어디가 틀렸는지
7. 다음 세트 진행, 반복

## 3. 지금까지 검토한 내용

### 3-1. 첫 시도: 영상 → 3D 재구성 (결과: 실사용 불가)
- 입력: `shoulder-press-final.mp4` (덤벨 숄더프레스, 1040×832, 24fps, 6.5초, 156프레임)
  - 실사가 아닌 **근육 해부도 스타일 일러스트**, **등 뒤 시점**, 같은 그림 두 개가 좌우로 붙어 있음
- 처리: 왼쪽 절반만 잘라 MediaPipe Pose(0.10.14, `mp.solutions.pose`, model_complexity=1)로 156프레임 전부에서 관절 33개 world landmark 추출 (실패 프레임 0) → 앞뒤 5프레임 이동평균으로 떨림 보정 → three.js로 마네킹 재구성
- 결과 문제점:
  - 등 뒤 시점이라 어깨가 실제보다 안쪽으로 잡힘
  - 카메라 1대라 깊이(앞뒤) 추정이 부정확 → 옆에서 보면 양팔이 앞뒤로 어긋남
  - 대연 판단: **"이건 못 쓴다"**
- 교훈: 실패 원인은 기술보다 **입력 영상 조건**(일러스트, 등 뒤 시점, 단일 카메라)

### 3-2. 기술적으로 가능한 부분 (Claude 검토 의견)
- 앱 흐름(부위 선택 → 추천 → 시간·기구 → 세트 안내)은 일반 앱 로직. 기존 운동 플래너(4분할 루틴 생성)를 확장하는 수준.
- 포즈 추정은 폰에서도 실시간 가능 (MediaPipe Pose Landmarker, Apple Vision, ML Kit 등).
- 숄더프레스 기준으로 반복마다 뽑을 수 있는 지표:
  - **가동범위**: 내렸을 때 팔꿈치 각도, 올렸을 때 팔이 펴진 정도
  - **템포**: 올리는 시간 / 내리는 시간
  - **좌우 대칭**: 양팔 높이·각도 차이
  - **상체 기울기**: 허리가 뒤로 젖혀지는지
- 세트 종료 후 분석(실시간 아님) 구조는 처리 부담이 적고 정확도에 유리 → 좋은 선택.

### 3-3. 설계 시 주의할 점 (Claude 제안)
1. **기준 영상과 사용자 영상의 촬영 각도를 통일**해야 한다.
   - 정면: 좌우 대칭, 팔꿈치 벌어짐이 잘 보임
   - 측면: 상체 젖힘, 팔 궤적이 잘 보임
   - 운동별 촬영 가이드 필요 (예: "폰을 정면 2m, 허리 높이에 두세요")
2. **영상끼리 프레임 단위로 비교하지 말고, 기준 영상에서 "규칙"을 추출**하는 방식이 안정적.
   - 예: 팔꿈치 각도 범위 70~165°, 올리기 약 1초, 내리기 약 2초, 좌우 차이 10° 이내
   - 사용자 동작이 범위를 벗어났는지로 판정 (체형·팔 길이 차이에 강함)
3. **운동 종류별 인식 난이도 차이**
   - 덤벨·바벨 프리웨이트: 잘 됨
   - 머신: 기구에 몸이 가려지는 경우 많음
   - 숙인 자세(리어델트 플라이 등): 관절이 겹쳐 정확도 낮음
   - → 초기엔 인식이 잘 되는 운동 위주로 시작
4. **가장 큰 비용은 콘텐츠**: 운동마다 제대로 찍은 기준 영상 + 잡을 오류 기준을 하나씩 정의해야 함

## 4. 도구 역할 분담 (Claude 제안)
- **채팅**: 기획·설계 (운동별 오류 항목, 촬영 가이드, 피드백 문구, 아키텍처)
- **Claude Design**: 화면 흐름 목업 (부위 선택 → 추천 → 세트 진행 → 피드백)
- **Claude Code**: 실제 구현과 검증 (로컬에서 MediaPipe 설치, 실제 영상 처리, 앱 빌드)

## 5. 제안 진행 순서

### Phase 1 — 비교 로직 검증 (Python 스크립트)
- 입력: 같은 운동을 **같은 각도(정면 권장)**에서 찍은 실사 영상 2개
  - 기준 영상 1개
  - 대연이 직접 1세트 수행한 영상 1개
- 처리:
  1. 프레임별 포즈 추출 (MediaPipe)
  2. 반복 자동 분리 (손목 높이 기준 피크 검출)
  3. 반복별 지표 계산 (가동범위, 템포, 좌우 차이, 상체 기울기)
  4. 기준 영상에서 기준값 범위 추출
  5. 사용자 반복별로 기준 이탈 여부 판정
- 출력: 앱에서 보여줄 형태의 피드백 (예: "3번째 반복: 왼팔이 덜 내려왔어요", "올리는 속도가 기준보다 2배 빨라요")
- 첫 대상 운동: **덤벨 숄더프레스, 정면 촬영**

### Phase 2 — 운동 확장 및 규칙 정의
- 운동별 설정 파일(촬영 각도, 측정 지표, 허용 범위, 피드백 문구) 구조 설계
- 어깨 운동 3~5개로 확장

### Phase 3 — 앱 구조 결정 및 구현
- 결정 필요: 포즈 분석을 **폰(온디바이스)**에서 할지 **서버**에서 할지
- 운동 추천 로직 (기존 운동 플래너 확장)
- 촬영 → 세트 종료 → 분석 → 피드백 → 다음 세트 흐름

## 6. 아직 정하지 않은 것
- 앱 형태 (네이티브 iOS/Android, 크로스플랫폼, 웹)
- 분석 위치 (온디바이스 vs 서버)
- 기준 영상 확보 방법 (직접 촬영 vs 외부 콘텐츠)
- 운동별 촬영 각도
- 피드백 전달 방식 (텍스트, 음성, 영상 위 표시 등)

```
이 문서(form-feedback-app.md)를 읽고 Phase 1을 진행해줘.

결과 확인용으로 반복별 지표 그래프와 관절 오버레이 영상도 만들어줘.
```
